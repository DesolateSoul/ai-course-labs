\Для развёртывания платформы автоматизации n8n использован Docker Compose. Конфигурация включает два сервиса: n8n (основной workflow-движок) и PostgreSQL (база данных для хранения настроек и выполненных execution). Настройка выполнена через файл docker-compose.yml с определением переменных окружения в файле .env. Платформа доступна по адресу http://localhost:5678. Для интеграции с YandexGPT настроены переменные YANDEX_IAM_TOKEN и YANDEX_FOLDER_ID, обеспечивающие аутентификацию при обращениях к LLM API.

\### 3.2. Базовый workflow

\Базовый workflow включает следующие узлы:

Webhook Trigger (basic-webhook) - точка входа для HTTP POST запросов, принимает JSON с полями message, contact, priority.

HTTP Request (YandexGPT) - выполняет POST запрос к YandexGPT API (endpoint: foundationModels/v1/completion) с промптом для классификации заявки. Модель возвращает JSON с категорией (tech/sales/complaint/general) и приоритетом (1-5).

Switch Node - реализует ветвление логики на основе полученной категории. Для tech-заявок направляет в техническую поддержку, sales - в отдел продаж, complaint - в отдел рекламаций, general - в информационную службу.

HTTP Request (Response) - формирует итоговый ответ клиенту с назначенным отделом и расчётным временем ответа.

\### 3.3. Интеграция с YandexGPT/GigaChat

\Для интеграции с российским LLM API использован YandexGPT через HTTP Request ноду в n8n. Конфигурация AI-ноды включает следующие параметры:

Endpoint: https://llm.api.cloud.yandex.net/foundationModels/v1/completion

Headers:

Authorization: Bearer {{ $env.YANDEX_IAM_TOKEN }}

Content-Type: application/json

Body (JSON):
```json
{
  "modelUri": "gpt://{{ $env.YANDEX_FOLDER_ID }}/yandexGPT/latest",
  "completionOptions": {
    "temperature": 0.3,
    "maxTokens": 200
  },
  "messages": [
    {
      "role": "system",
      "text": "Ты интеллектуальный модуль маршрутизации виртуальной АТС. Анализируй запрос и возвращай JSON с категорией и приоритетом"
    },
    {
      "role": "user",
      "text": "{{ $json.body.data }}"
    }
  ]
}
```
\
Ты интеллектуальный модуль маршрутизации виртуальной АТС. Твоя задача: проанализировать текст запроса абонента и вернуть JSON с параметрами маршрутизации. Формат ответа строго: {"category": "[tech/sales/complaint/general]", "priority": [1-5], "estimated_duration": [в секундах], "required_skill": "[skill_name]", "response_text": "[короткий ответ абоненту]"}.

Категории: 
- tech - техническая поддержка (сбои, ошибки, настройка)
- sales - продажи (подключение услуг, тарифы)
- complaint - рекламация (качество связи, списания)
- general - общие вопросы

Приоритет: 5 - самый высокий (критические сбои), 1 - низкий (информационные запросы).


\### 3.4. Специализированный workflow

Адаптированный workflow разработан для специальности "Математическое обеспечение и администрирование информационных систем" и темы диплома "Интеллектуальный модуль для виртуальной АТС". Workflow реализует интеллектуальную маршрутизацию входящих вызовов на основе анализа текста запроса через YandexGPT.

Схема для вашей специальности:

Узел 1 (Webhook Trigger) - приём POST-запросов от АТС на эндпоинт /webhook/ats-intelligent-routing

Узел 2 (YandexGPT Router) - классификация запроса через LLM, определение категории и приоритета

Узел 3 (Switch Node) - ветвление по категориям (tech/sales/complaint/general)

Узел 4 (ATS Routing API) - назначение оператора на основе приоритета и требуемой компетенции

Узел 5 (Response Formatter) - формирование ответа для АТС с информацией о маршрутизации

\### 3.6. Интеграция с дипломом

Разработанный workflow является прототипом интеллектуального модуля для виртуальной АТС, описанного в дипломной работе. В дипломной работе данный модуль выполняет следующие функции:

Автоматическая классификация обращений - анализ текста запроса абонента через LLM для определения категории проблемы (техподдержка, продажи, рекламация, общие вопросы)

Интеллектуальное распределение нагрузки - назначение приоритета обработки от 1 до 5 на основе критичности проблемы

Маршрутизация на операторов - выбор наиболее подходящего оператора на основе требуемой компетенции (required_skill) и текущей загрузки

Сбор статистики - логирование времени обработки, категорий вызовов и эффективности маршрутизации

Как workflow автоматизирует процессы диплома:

Заменяет ручное распределение вызовов оператором колл-центра на автоматическое

Сокращает время ответа абоненту с 30-60 секунд до 1-2 секунд (время обработки LLM)

Обеспечивает 24/7 доступность интеллектуальной маршрутизации

Позволяет собирать аналитику по типам обращений для оптимизации работы АТС
